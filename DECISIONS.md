# Clinic scheduling decisions

1. **One deployable application.** Keep Python/SQLite and replace the duplicate salon/Next.js/ElevenLabs surfaces with one responsive same-origin UI. Browser speech removes mandatory paid API setup. npm is needed only for browser development tests.
2. **Each doctor is a scheduling resource.** Weekly split shifts and date overrides produce slots whose stride is visit duration plus buffer. Other doctors can book the same time independently. Duration is fixed per doctor; distinct visit-type durations and rooms/equipment are future extensions.
3. **Hold the whole recurring series.** Validate all occurrences under one write transaction and roll back everything if one conflicts. Confirm rechecks availability and policy. The series is finite (up to 12 visits, 1–4 week spacing, 90-day horizon by default). No unbounded RRULE promises.
4. **UTC storage, local recurrence.** Build each recurring occurrence from its clinic-local wall date/time, then convert to UTC. A series at 09:00 stays at 09:00 when the UTC offset changes. Ambiguous/nonexistent start times are excluded instead of guessed.
5. **Separate capability and staff access.** Public availability exposes no patient records. Patient management requires a random reference and HMAC-derived private numeric code; the booking group stores a code hash. Numeric credentials can be entered over DTMF. A persisted database secret makes idempotent confirmations return the same code. Short-lived call receipts contain confirmation data and are treated as sensitive. Staff use salted scrypt passwords, expiring HttpOnly sessions, roles and CSRF tokens.
6. **Voice is a channel.** Explicit stages and constrained choices invoke the same engine as the booking UI. No LLM chooses a time or creates a booking. Call turns carry sequence and retry keys; sessions persist for 30 minutes. Silence/invalid responses are bounded and refer the caller to staff after three failures. Unconfirmed holds expire independently after five minutes.
7. **Free browser operation; optional paid PSTN.** Web Speech APIs need no app keys, but provider/browser speech support varies and recognition can be cloud-based. The optional Twilio adapter validates signed form webhooks using the configured public URL. A phone-number trial is an evaluation path, not an unlimited free service.
8. **Protect existing commitments.** Availability edits that invalidate live bookings/holds roll back. Doctor duration/buffer/deactivation changes with live bookings also fail. Staff may override the patient cancellation cutoff for future appointments; past visits remain immutable.
9. **No fictional integrations.** The clinic database is authoritative. No calendar synchronization, SMS delivery, billing, insurance checks, clinical advice, or reminder delivery is implied. These require explicit adapters and operational setup.
10. **Single-process first.** SQLite serializes booking writes across connections; a process-level lock serializes call turns. Multiple workers need shared call locking, shared rate limiting, and a migration path to an appropriate shared database. This version deliberately documents that boundary.
